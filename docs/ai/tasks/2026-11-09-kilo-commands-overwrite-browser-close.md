## 背景

- 現行のグローバルコマンドは、assess-items が v10 相当（10,892バイト）、implement-items が v11 相当（12,171バイト）です。
- 課題：現行ルールでは、UI項目の画面確認でサブエージェント（子）が項目ごとに Playwright のブラウザを開きますが、終了時に閉じる工程が無規定のため、子の早期終了（不合格・未解決・判断の持ち帰り等）の経路でブラウザが開いたまま残り続けます。
- 対応方針：画面確認の置き場所は変えません（親へ集約すると、重い画面確認が親のコンテキストを圧迫し、サブエージェント化の効果が薄れるため）。代わりに「開いた子がその場で閉じる」規律と、親側の残存チェックで漏れを止めます。
- assess-items 反映版（v12、12,918バイト）の変更は次のとおりです（発行側で現行版との差分がこの範囲だけであることを確認済み）：
  - 深掘りの子の手順2に開閉の規律を追加：ブラウザはその項目の画面確認のためだけに開き、Drive保存とタスクへの記録が終わったら、その場で Playwright browser tool の終了操作で必ず閉じる。どの終了経路でも、結果を返す時点でブラウザは閉じていること。閉じられない場合はその旨と理由を結果に明記する
  - 子の結果の要約に「ブラウザを閉じたかどうか（開かなかった場合はその旨）」を追加
  - 子への制約に「開いたブラウザは、成否・終了経路によらず、結果を返す前に必ず閉じる。閉じた旨の無い結果は未完了として差し戻される」を追加
  - 親の手順1で、Playwrightのブラウザ本体プロセスを識別する条件（コマンドラインに含まれる専用プロファイル／一時フォルダのパス等。MCPサーバー本体は含めない）を実プロセス確認で1つ定め、共通コンテキスト要約に含める
  - 親が子の結果を受ける際の確認に、ブラウザ残存の計数を追加。残存がある場合は、識別条件に一致するブラウザ本体プロセスだけを親が終了させ、件数を記録する（項目の合否には含めない）
  - 深掘り項目について親は Playwright を操作しない旨を制約に明記（親のブラウザ関連作業は残存の計数と終了だけ）。直接方式（対象3件以下で親が調査する方式）で親が開いたブラウザは、項目ごとに必ず閉じる
  - 完了報告に「ブラウザ残存の確認結果（項目ごとの残存数と、親が終了させた件数）」を追加
- implement-items 反映版（v13、14,178バイト）の変更は次のとおりです（発行側で現行版との差分がこの範囲だけであることを確認済み）：
  - 子の手順3に、assess と同じ開閉の規律を追加（Drive保存と記録の後、他の工程へ進む前に必ず閉じる。未解決時の手順5にも、返す前に閉じる旨を追加）
  - 子の結果の要約に「ブラウザを閉じたかどうか」を追加し、子への制約に close 義務と差し戻し条件を追加
  - 親の手順1でブラウザ本体プロセスの識別条件を定めて共通コンテキスト要約に含め、手順2cの機械的確認に残存の計数と残存終了を追加
  - 親は Playwright を操作しない旨を制約に明記（親のブラウザ関連作業は残存の計数と終了だけ）
  - 完了報告に「ブラウザ残存の確認結果」を追加
