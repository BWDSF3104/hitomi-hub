## 調査結果 / 変更内容

有効（静的＋実測補助）。`processFile` は常に `Sha256File`（`app/main.go:491` 相当）。size/mtime で skip する分岐がなく、cache は VT verdict 専用（`scan_status = cached`）。scratch root 5 ファイルで scan を 2 回実行（0.262s/回）→ 2 回目も全 file を再ハッシュして findings を再 insert。対応: `scan_cache(sha256,size,mtime)` テーブルで unchanged を skip（scan_status は維持）。合格条件: 2 回目 scan でファイル读取が hash 1 回未満、findings/scan_status が 1 回目と同一。推定規模: 小〜中。

実施（2026-11-04・承認済み方針 A-12 条 `2026-11-03-remaining-item-recommendations-approved.md`）:

- `schema.sql`: `scan_cache` に `size INTEGER` / `mtime INTEGER`（nullable）追加。`schemaVersion` 4 → 5。
- `app/main.go` `migrateSchema`: 既存 DB には `ensureScanCacheSizeMtime`（列追加のみ・既存行削除禁止・D-03 非破壊迁移規約）。正典 `hitomi.db` は今すぐ手入れせず次回 `ensureSchema` で揃う（D-03 承認済み）。
- `processFileWithYara`: skip 分岐（`scanSkipStatus`）。`scan_cache(sha256,size,mtime)` を `files`（path→sha 記録）経由で引き、size/mtime 一致で skip（scan_status 維持・findings 再 insert なし・YARA/VT gate 非実行）。不一致（size/mtime 差異・列 NULL・record なし・external_removal）は再ハッシュ（安全側）。skip 時に `summary["skipped"]` を加算（scan 出力 JSON に `skipped` キー追加）。
- `recordScanMeta`: scan 完了時に scan_cache へ size/mtime を記録（既存 VT verdict 行は size/mtime のみ更新・verdict/cached_at（TTL 判定）不変。scan meta 行は verdict='' なので `cacheLookup` は miss → VT gate 挙動は既存と同一。negative cache・B-07 `scan_source` 表現・gate/quota 回数は変更なし、skip は gate 回数を増やさない）。
- テスト計測用 hook `hashFunc`（既定 `Sha256File`）。
- 留意: scan_cache は sha256 キーなので同一内容の複数 path は mtime を 1 行にしか持てず、path 間で不一致 → 安全側で再ハッシュに退化（正しさは維持）。
